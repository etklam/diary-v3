## Anti-Patterns Verdict

**Deterministic scan**: `detect.mjs` over `apps/web/app` returns 2 findings, both trivial —
a pass-through `<img>` in `markdown.tsx:21` (false positive, it is a markdown renderer) and
one undocumented `#cbd0d7` in `market-rotation.tsx:761`. None of the saturated AI tells are
present: no gradient text, no cream body, no glassmorphism, no ghost cards, no over-rounding,
no side-stripes, no repeating-linear-gradient. `--shadow-1: none` is genuinely enforced.

**LLM assessment**: it does not read as generic AI output, but it has a different and more
specific AI signature — **uniformity substituted for judgment**. Three symptoms:

1. **Prose where structure should carry the meaning.** The same priced/unpriced caveat is
   written three times in near-identical words: `overview.tsx:26` "Priced positions only;
   unpriced cost remains separate.", `portfolio-valuation.tsx:11` "Values cover priced
   positions only. Unpriced cost remains separate." and "Concentration uses priced market
   value only." A designer draws one line and footnotes it once; an LLM writes the sentence
   again at each site.
2. **One texture on every surface.** Hairline + label-above-value + sentence-case heading,
   at the same type scale and the same spacing, on capture, on tables, on reading. No
   surface earns a different density.
3. **No severity encoding.** `portfolio-attention.tsx` orders its items by priority in data.
   On screen all five rows are the same weight with the same "Open" link at the same x. An
   overdue review and a missing thesis look identical.

## What's Working

- **The token system is real and enforced.** 74 contrast pairs pass in each theme, market
  colours invert correctly for the `cn` preference and clear the action hue for `cb`,
  `--shadow-1: none` holds app-wide. This is a stronger foundation than most products have.
- **Keyboard affordances are discoverable, not hidden.** ⌘K on the search field, ⌘/Ctrl J
  under the Quick diary button, ⌘/Ctrl Enter beside Create diary — printed inline rather
  than left for a shortcut sheet.
- **Error recovery is consistent.** `FailureNotice` + an explicit retry button appears the
  same way on every async surface.

## Priority Issues

### [P1] No feedback between a navigation click and the next paint
`useNavigation()` appears zero times in `apps/web/app`. This is a React Router SSR app whose
loaders hit the API, so every sidebar click leaves the old page on screen with nothing
indicating work started. This is the main cause of "not smooth"; it is not a styling problem.
**Fix**: a global determinate-ish top progress bar driven by `useNavigation().state` in
`root.tsx`, plus optimistic active state on the clicked nav item, plus `<Link viewTransition>`
on same-shell navigations. Also replace the label-swap pending pattern
(`busy ? t('pending') : c.save`) — it reflows the button width mid-submit.
**Suggested command**: `$impeccable animate`

### [P1] "Needs your attention" ranks nothing and names nothing
Five rows, identical weight, identical trailing "Open" link roughly 1,150px from its own
label. Three of them are the same kind ("Missing thesis" × AAPL, MSFT, SYN). The data is
already priority-ordered; the layout discards that.
**Fix**: make the whole row the link and delete the trailing "Open"; give the verb to the row
("Review overdue diary", "Add a thesis for AAPL"); encode severity with a leading rule weight
or a left-edge marker rather than a tint; collapse same-kind items into one grouped row with
a count.
**Suggested command**: `$impeccable layout`

### [P1] The design system has exactly one density
Capture, ledger and reading surfaces all use the same type scale, the same `--space-5`
rhythm and the same hairline. Quick diary — the product's core capture surface — puts a
690×280 textarea in the top-left of a 1,225px canvas and leaves ~550px of nothing below the
fold; the mobile diary reading page runs 2,984px with every section heading at the same rank,
so "Guru context at decision time" sits level with "Transactions".
**Fix**: name three density modes in DESIGN.md (capture / ledger / reading), each with its own
measure, spacing step and heading scale, then assign every route to one. Give reading surfaces
a real h2/h3 split so secondary modules drop a rank.
**Suggested command**: `$impeccable layout`

### [P2] Sentences are doing the work that structure should do
The triple-written priced/unpriced caveat is the clearest case, and the pattern repeats:
`/stocks` carries four full-width prose sentences interleaved between the label/value pairs of
its valuation grid, so the scan breaks four times.
**Fix**: one footnote affordance anchored to the figure it qualifies, written once; move the
rest to a single "How these figures are calculated" disclosure at the foot of the region.
**Suggested command**: `$impeccable clarify`

### [P2] The system is unfinished at its native edges, and its primaries start disabled
`<details>` is used 37 times in TSX and only 23 summaries carry a class, so the native ▶
marker ships next to carefully-built custom controls (visible on "Capture reminder",
`quick-capture-tools.tsx:11`). Eight routes ship a disabled filled primary as their resting
state; on Quick diary that disabled button is the first thing the user sees on the core
capture screen. "Quick diary" also renders twice on `/` — sidebar and page header, both filled.
**Fix**: one styled `<Disclosure>` component, used everywhere; either enable the primary and
validate on submit, or name the precondition beside the control; drop the duplicate header action.
**Suggested command**: `$impeccable polish`

### [P2] Mobile runs two navigation systems and puts delete in prime position
`/diaries/:id` at 390 shows a top-right "Menu" button, a separate search icon, and a five-item
bottom tab bar on the same screen. At the foot of that 2,984px page, `Delete diary` is the
left-most (primary-position) button, with `Write a diary` to its right.
**Fix**: pick one mobile nav (the bottom bar; let Menu hold only overflow); move destructive
actions out of the footer row into the entry's own overflow menu, behind a typed confirm
rather than `window.confirm`.
**Suggested command**: `$impeccable adapt`

## Persona Red Flags

**Alex (power user)**: ⌘K and ⌘/Ctrl J are there and good. But no bulk actions anywhere —
three "Missing thesis" items must be opened one at a time; no multi-select on Holdings or the
review queue. Clicking a nav item gives no response, so Alex clicks twice.

**Sam (accessibility)**: contrast is genuinely handled (74 pairs per theme). Gaps: route
changes announce nothing to a screen reader because there is no live region on navigation;
severity on the attention list is conveyed only by row order, which is invisible to a linear
reader; 14 unstyled `<details>` have inconsistent announced state against the 23 styled ones.

**Casey (mobile)**: the primary action on the diary page (`Edit diary`) is at the very top,
2,900px from where the user finishes reading. Transactions render six "—" placeholders in a
row, so the screen reads as broken rather than empty. Two nav systems compete for the same
thumb.

## Minor Observations

- `Holdings`: the "Quote status" column is the widest in the table, wraps to two lines, and
  repeats "Stale quote · Sep 4, 2026, 3:00 PM UTC" identically three times — maximum width for
  minimum decision value. Collapse to a marker plus one "as of" line under the table.
- The same page then restates it twice more in prose ("Oldest quote:", "Quotes older than
  72 hours: 3").
- Table headers wrap mid-phrase ("Average / cost", "Current / price", "Market / value").
- `#cbd0d7` at `market-rotation.tsx:761` is outside the DESIGN.md palette.
- 24 `transition:` declarations and 1 `@keyframes` across every stylesheet in the app. Motion
  is effectively absent rather than deliberately restrained.
