## Private review correction

Frozen `server/utils/user-queries.ts` spreads full Diary scalar rows into both `getSystemStatsAdmin().recentActivity.diaries` and `listAllDiariesAdmin`, which would include newly added private Review text. PRD story33 requires private Review text to be readable only by its owner. Preserve admin account/count/Diary operations while using explicit admin Diary projections that omit private outcome/reflection summary/learning/adjustment fields. Audit the exact schema field names and every admin projection, including recent activity. Ordinary owner Review reads remain unchanged. Record this intentional legacy correction in ADR0001 when implemented, with synthetic secret-marker regression evidence; do not present it as unchanged source wire behavior.

## Authentication and persistence

Use the existing per-request authoritative user role/session lookup. A role downgrade must take effect on the next Admin request; stale JWT role claims must not retain Admin access. Preserve source semantics for role changes without inventing another token system. Deleting an account removes its real dependent data and revokes current HTTP/refresh/API-key/Socket access, after commit; failed deletion must not disconnect an account that still exists. Reuse the existing runtime revocation callback and DB cascades, inspecting all current ownership/partner relationships first. Two concurrent administrators must not bypass self-modification restrictions or cause partial cleanup; use meaningful real PostgreSQL tests.

Validate Admin versus ordinary User, self-action rejection, unknown IDs, search/pagination, role downgrade using an already issued token, and deleted account access from multiple Web/native/Socket clients. Another user's data and connection must survive. Inspect desktop/light and390px/dark in one bounded pair after the actual flows work. No production user management is authorized by this development ticket.
