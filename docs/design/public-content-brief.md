## Public search implementation boundary — runtime corrected

The frozen source constructs an OR of title and excerpt Prisma search predicates, but the frozen generated Prisma client combines them into `MATCH (excerpt,title) AGAINST (? IN BOOLEAN MODE)`. The real MariaDB probe in `docs/parity/post-fulltext-probe.json` supersedes the earlier static inference of independent field matching. A multi-term required query can match across title and excerpt. Content does not participate.

The controlled MariaDB11.4.13 probe uses utf8mb4_unicode_ci, the source combined full-text index, minimum token length3 and enabled stop words. It records exact words, partial nonmatches, prefix wildcard, required terms, phrases, Chinese contiguous versus short separated tokens and accent-insensitive matches. Preserve these observed semantics in PostgreSQL; admin substring search remains separate. The probe is search-only, not a claim that a complete legacy API suite ran. Use its emitted SQL and synthetic rows as reproducible baseline evidence.

Additional observed Boolean cases and the actual InnoDB stop-word list are in `docs/parity/post-fulltext-boolean-probe.json`. Optional terms are OR; required/excluded terms and grouping alter membership; short/stopword prefixes can match longer indexed words. Although MATCH combines fields, a quoted phrase does not bridge the title/excerpt boundary. Apply the minimum-token and stop-word rules to indexed document terms as well as queries; a generic PostgreSQL simple vector alone is not equivalent.
