# Shared prompt management

Scope: `/admin/ai/prompts`, Operate mode. Admins inspect immutable source defaults, prepare versioned guidance, run a bounded synthetic capability test, then choose a production override.

## Direction contract

THESIS: Prompt provenance is the organizing fact. The current effective source remains visible while an admin inspects a different version.

OWN-WORLD: Extend the existing Ledger tokens, native selects, ruled panels, readable template field, restrained filled save action, and quiet secondary controls. Use the existing danger treatment for archive and disable.

STORY: Select the module and version, inspect its code-owned contract, prepare a new immutable version, preview or test registered synthetic input, then activate or roll back with a named consequence.

FIRST VIEWPORT: Heading and task sentence, two native selectors, effective source and registry revision, then the editor. Reference, playground, and audit follow in reading order. The template is the largest control; JSON details expand only when needed.

FORM: Extend the existing management grammar. The supplied DESIGN.md is the direction authority; no new visual world or catalog seed is introduced.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Evidence and rationale

Before: AI Reports exposed weekly/monthly prompt drafts inside `/admin/ai`, with database defaults and report-specific publication controls. The baseline screenshot is `.scratch/ui-score/admin-ai-1440.png`.

After: a dedicated shared registry exposes source defaults separately from overrides and keeps provenance above editing. JSON contract and synthetic input are disclosures, preserving the operator's first task and reducing scrolling. Screenshots and runnable browser evidence live in `docs/design/evidence/shared-prompts/` and `tests/e2e/shared-prompts.spec.ts`.

No shipping raster assets are added. Evidence screenshots contain synthetic prompts and provider identities only.

## Finish verdict

Accepted after the desktop/mobile/light/dark evidence review and one correction batch. The final browser acceptance run passes the complete lifecycle and immediate test-audit refresh. The source and override distinction is visible before editing; actions wrap at narrow widths, destructive operations use the established danger treatment and a consequence dialog, and the editor uses a bounded 72ch measure. No shipping raster assets were introduced.
