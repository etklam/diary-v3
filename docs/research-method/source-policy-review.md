# Source-policy review

Reviewed: 2026-09-25 (Asia/Taipei). This is an operation-scoped implementation record, not a licensing platform or a live-source enablement decision. The linked terms were reviewed; no live Yahoo, BLS, Tavily, or research-content request was made.

## Policy rules

Record `allowed`, `restricted`, or `unknown` separately for automated fetch, evidence storage, LLM inference, publication of analysis and excerpts, and raw-data redistribution. Every `allowed` decision needs a valid HTTPS basis URL and ISO check timestamp. A status-only `allowed` value is treated as `unknown`. Unknown or restricted rights block only that operation. An administrator recording a decision does not create rights; a public-term permission does not need a separate written license when it covers the exact content and use. Apply contrary notices, third-party rights, source-specific exceptions, and access conditions before use.

Keep acquisition unknown until each exact route and applicable access terms are checked.

BLS states that its published material is public domain, except previously copyrighted photographs and illustrations, and asks users to cite BLS. This review applies that statement only to BLS-origin text/data. Exclude third-party content and notices that reserve rights; do not use the BLS emblem or other BLS trademarks without authorization. The separate public API terms require the API retrieval date and a statement that BLS cannot vouch for post-retrieval data or analyses; they also prohibit modifying or falsely representing BLS content and make API use subject to access limits. The report renderer now includes a retrieved timestamp in validated citations and conditionally appends the required BLS disclaimer for successfully retrieved BLS-hosted sources. No exact BLS API endpoint is configured, so this does not enable an API route: its exact route, access conditions, and source-specific use must still be verified. These content-use conclusions do not independently approve a particular automated route.

The current adapter requires a configured owner email for BLS-hosted requests, includes it in the User-Agent, caps each preparation at ten configured official sources, and processes those requests serially. It has no shared cross-run rate limiter. Therefore, an operator must still configure a non-excessive rate and verify the exact endpoint before marking automated fetch allowed. No contact value is supplied by default.

## Evidence and unresolved questions

- [BLS copyright information](https://www.bls.gov/opub/copyright-information.htm): first-party published material is public domain except previously copyrighted photographs and illustrations; BLS requests attribution.
- [BLS terms of use](https://www.bls.gov/bls/blsterms.htm): excessive robot activity is prohibited; BLS reserves the right to block robots without owner contact information.
- [BLS API terms](https://www.bls.gov/developers/termsOfService.htm): cite API retrieval dates, include the BLS post-retrieval disclaimer, do not modify or falsely represent BLS content, and respect access limits.
- [Federal Reserve disclaimer](https://www.federalreserve.gov/disclaimer.htm): apply the Board's own-information reuse scope and attribution; do not extend it to linked third-party sites.
- [BEA copyright FAQ](https://www.bea.gov/help/faq/147): use BEA material only where no contrary notice applies and retain provenance/attribution.
- [Yahoo Terms of Service](https://legal.yahoo.com/ca/en/yahoo/terms/otos/): the reviewed regional page restricts automated collection without express prior permission. It supports keeping the adapter blocked, but this review does not determine that the Canadian regional terms govern this account.
- [Tavily Search API reference](https://docs.tavily.com/documentation/api-reference/endpoint/search) and [Tavily terms](https://www.tavily.com/terms): the API reference does not establish the user's account entitlement; the terms refer to plan/order terms and separately define AI functionality. The terms page reviewed here was last updated 2026-05-04.

Unresolved source questions remain separate:

1. Yahoo: Which applicable Yahoo/data-provider agreement permits this application's automated chart retrieval and downstream analysis/excerpt uses? The current Canadian English terms page may not govern this account, so the endpoint's live research use stays unknown.
2. Tavily account and limits: Which actual account plan, API key terms, and order form cover this service, and what request, credit, fee, and overage limits apply? No key/account entitlement or plan was supplied for this adapter.
3. Tavily result handling: May this service retain search-result metadata and snippets in private evidence snapshots, for what duration, and may it send those fields to its separate LLM for inference or publication? The current API reference does not answer these account-specific data-use questions.
4. Tavily AI functionality and investment use: Is this workflow's Search API request and result metadata distinct from Tavily's separately defined AI functionality and its Outputs? The current terms prohibit using Tavily AI Functionality or its Outputs in connection with financial investment decisions. They also allow Tavily and its third-party AI providers to process and retain AI-functionality inputs/outputs for training and service improvement, and allow fees for AI functionality after a limited free-trial period. Do not use that functionality or its Outputs for this workflow. Before enabling `/search`, verify it is distinct from those AI features and determine query/result handling under the actual account and plan.
5. Issuers and company IR: Which issuer-specific terms apply to each exact URL and extracted item, what route/rate authorizes automated retrieval, and which storage, LLM, excerpt-publication, and redistribution uses are permitted? Do not infer iShares permission or endpoint identity from a hostname.
6. BLS route: Which exact CPI/employment event URL or API response will be configured, what content-specific notices apply to it, and what non-excessive rate is appropriate for that route? The owner-contact guard is necessary but is not a substitute for those checks or a global rate limit.

No source is upgraded based only on endpoint availability or a synthetic fixture. Raw-data redistribution is independent from attributed analysis/excerpts and is not required for the report workflow. Synthetic sources may use explicit test policies but remain ineligible for article publication.
