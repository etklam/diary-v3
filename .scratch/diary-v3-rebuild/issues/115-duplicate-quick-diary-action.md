# [115] Rule on the duplicate Quick diary primary action

Status: needs-triage

## Observation

Recorded in the [whole-app page score](../../../docs/design/ui-page-score-2026-10-06.md)
and carried in [112](112-empty-states-and-list-sections.md)'s Observation as deliberately
unfiled pending a ruling. Filed here by [112](112-empty-states-and-list-sections.md)'s
execution rather than dropped.

**Two identical filled `Quick diary` actions are visible at once** on the workspace pages
that carry a page-level one:

| Where | Source |
|---|---|
| Sidebar, above the navigation list | `quick-entry.tsx:33` — `.button.quick-capture-primary`, `data-testid="quick-entry"` |
| Overview, top right of the content area | `overview.tsx:213` |
| Diary library, top right of the content area | `routes/diary-list.tsx:356` |

Both link to `/diaries/quick`, both are filled, and on Overview and `/diaries` both are on
screen simultaneously. `DESIGN.md` asks for one filled action per surface.

**There is a defensible reading in which this is correct**, which is why it is a decision
and not a bug: the sidebar one is the global shortcut, available on every private page and
paired with the `Cmd/Ctrl+J` hint; the page one is the contextual primary action of a page
whose subject is diaries. The product's standing rule is that navigation serves capture →
read → review before anything else, so demoting *either* needs an argument rather than a
style rule.

## Requested outcome

One ruling, applied consistently across every workspace page, recorded against the
capture-first principle. Preserve the keyboard path (`Cmd/Ctrl+J`), the mobile bottom-bar
capture entry, and the `quick-entry` / `mobile-quick-entry` test ids that the preference
and navigation helpers depend on.

## Implementation plan

**1. Decide which one carries the filled weight.** Candidates: keep the sidebar filled and
make the page-level action secondary, which leaves one filled capture mark on screen and
keeps the global shortcut as the thing that is always in the same place; or keep the page
action filled and quiet the sidebar entry, which gives the page its own primary and makes
the sidebar read as navigation; or state that both are intentional and amend `DESIGN.md`
so the rule stops being contradicted by the delivered product.

**2. Apply it to every page that carries a page-level capture action**, not only Overview
and Diary library — audit the workspace pages for the same pattern first.

**3. Check the mobile shell separately.** Below 768px the sidebar becomes a top bar plus a
bottom bar whose first item is capture, so the duplicate may present differently or not at
all there.

**Verification:** `overview.spec.ts`, `diary-list.spec.ts` and `workspace-navigation.spec.ts`
must pass. Add one assertion that a workspace page shows the agreed number of filled
capture actions at 1440 and 390.

- [ ] `Cmd/Ctrl+J`, the mobile bottom-bar capture entry and the existing capture test ids are unchanged.
