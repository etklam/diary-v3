# [134] Cache the Intl formatters the figure conventions build

Status: ready-for-agent
Execution: done
Published: 2026-10-25
Completed: 2026-10-25

Category: bug
Type: Performance
User stories covered: None directly; affects every page that prints a table of judged
figures — holdings, performance, relative value, guru comparison, timeline, calendar.

## Observation

`apps/web/app/market-display.ts` constructs a fresh `Intl` object on nearly every call.
`decimalSeparator` caches its lookup (`separatorCache`), but the two formatting sites do not:

- `groupInteger` calls `new Intl.NumberFormat(...)` per invocation, so every `formatAmount`,
  `formatSignedAmount`, `formatQuantity`, `formatCount`, `formatPercent` and
  `formatSignedPercent` builds one.
- `formatInstantIn` calls `new Intl.DateTimeFormat(...)` per invocation, so every
  `formatInstantUtc` / `formatInstantLocal` builds one.
- `formatMarketValue`, `formatNeutralValue` and `formatCompactUsd` each build their own
  directly.

Construction, not formatting, is the cost. Measured 2026-10-25 against the real exported
functions:

| Call | Cost |
|---|---|
| `formatAmount(locale, "182.4")` | 9.67 µs |
| ⮑ of which `new Intl.NumberFormat(...).format()` | 8.58 µs |
| `formatInstantUtc(locale, iso)` | 24.78 µs |
| ⮑ of which `new Intl.DateTimeFormat(...).format()` | 26.13 µs |
| A reused `NumberFormat.format()` | 0.28 µs |
| A reused `DateTimeFormat.format()` | 1.24 µs |

These are per-cell costs because the call sites are per-cell: `routes/holdings.tsx:71-80`
formats seven figures inside `data.holdings.map(...)`, and 133 call sites across
`apps/web/app` follow the same shape. Measured with that exact seven-figure row:

| Holdings rows (×7 figures) | Before | After | |
|---|---|---|---|
| 10 | 0.85 ms | 0.04 ms | 23.5× |
| 30 | 2.89 ms | 0.11 ms | 25.4× |
| 50 | 4.33 ms | 0.18 ms | 23.7× |
| 200 | 16.93 ms | 0.73 ms | 23.3× |

Median of five runs, 1,000 iterations each after 50 warm-up iterations, both modules in one
process so the comparison shares a machine and a JIT state.

Measured on an Apple-silicon laptop, so a mid-range phone is roughly 3–5× worse, and the
cost is re-paid on every sort, filter and quote-driven re-render rather than once per page.

**Severity is modest and should be stated honestly.** 2–4 ms on a holdings page is not a
visible defect today. This is worth fixing because the correction is a dozen lines with no
behavioural surface, not because a page is slow.

## Requested outcome

Formatters are built once per locale-and-options combination and reused, with the rendered
output proven unchanged.

## Implementation plan

**1. Cache by locale and options.** Add module-level `Map`s keyed on the locale plus a
discriminator for the options set, matching the existing `separatorCache` idiom in the same
file. Route `groupInteger`, `formatInstantIn`, `formatMarketValue`, `formatNeutralValue` and
`formatCompactUsd` through them. The caches are bounded in practice by the three supported
locales times a fixed set of option shapes, plus one entry per distinct IANA zone reaching
`formatInstantIn`.

**2. Prove output equivalence, not just speed.** The existing
`tests/unit/market-display.test.ts` and `tests/unit/figure-formatting-boundary.test.ts`
already pin the conventions; extend them so a reused formatter is shown to produce the same
string as a fresh one across locales, including the signed, zero, padded, rounded and
non-numeric paths and more than one time zone.

A prototype of this change — the same module with only the two construction sites cached —
was compared against the live module over three locales × eighteen values × nine numeric
functions plus the instant functions in both UTC and `Asia/Taipei`, and produced identical
output in every case.

**Verification:** `npm run lint`, `npm run typecheck`, `npm run test:unit`, and
`npm run design:check` (`scripts/check-figure-rule.mjs` governs this file's conventions).

## What was built

Two module-level caches in `apps/web/app/market-display.ts` — `numberFormat(locale, shape,
options)` and `dateTimeFormat(locale, timeZone)` — following the `separatorCache` idiom
already in that file. All five construction sites route through them: `groupInteger`,
`decimalSeparator`, `formatMarketValue` (keyed by digit count), `formatNeutralValue` (keyed
by digit count) and `formatCompactUsd`; `formatInstantIn` takes the date cache. No `new
Intl.` call remains outside the two helpers.

A cache is only safe if a distinction it does not key on cannot exist, so the new
`formatter reuse` block in `tests/unit/market-display.test.ts` interleaves exactly the
variants that share a function: locales in both directions, digit counts, and time zones.

### Acceptance — 2026-10-25

Equivalence was established before the change, against a prototype copy of the module:
three locales × eighteen values × nine numeric functions, plus the instant functions in UTC
and `Asia/Taipei` — identical output in every case.

Per call, on the shipped module: `formatAmount` 9.67 → 0.42 µs, `formatQuantity`
8.98 → 0.40 µs, `formatSignedPercent` 8.92 → 0.38 µs, `formatInstantUtc` 24.78 → 0.83 µs.

A first pass reported only 5.8× on the table benchmark. That was a measurement fault, not a
result: the cached column was given one warm-up iteration, and at sub-millisecond cost the
warm-up dominated. Re-measured as an A/B in one process with 50 warm-up iterations and a
median of five runs — the numbers in the table above — it is ~23×, and the uncached column
reproduced its original figures.

Gates: `npm run lint` clean, `tsc --noEmit` clean, `npm run test:unit`
**136 files / 1215 tests pass in 14.5s** (`tests/unit/market-display.test.ts` 15/15, four of
them new), `npm run design:check` passes — including `scripts/check-figure-rule.mjs`, 88
tabular-figure blocks checked — and `vite build apps/web` succeeds.

Not verified: the e2e suites, which need PostgreSQL and were not run. No API contract,
schema or copy changed, so `contracts:check` and `manifests:check` were not required.
