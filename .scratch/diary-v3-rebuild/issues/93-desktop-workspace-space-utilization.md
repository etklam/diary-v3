# [93] Use desktop workspace width more effectively

Status: needs-triage
Execution: todo

Category: enhancement
Type: Design follow-up
User stories covered: Cross-cutting workspace and Admin usability.

## Observation

Several pages leave a large unused region on the right at desktop widths while their working content stays narrow. The Admin article editor at `/admin/blog/:id/edit` and pages under `/diaries/*` are concrete examples. This affects how much useful context and editing work can be seen at once, and makes some pages feel anchored to one side of a much wider workspace.

The empty area is a symptom to investigate, not a requirement to stretch every content block. Long-form reading still needs a bounded measure, and a page may intentionally stay narrow when that supports its task.

## Requested outcome

Audit desktop workspace and Admin pages for layouts that underuse the available width. Include every route under `/diaries/*` and the article editor in the initial audit. Design desktop and mobile as distinct, intentional layouts: desktop should make useful use of horizontal workspace; mobile should arrange the same task for touch and a narrow viewport rather than simply shrinking the desktop composition. Define the tablet transition, then implement the agreed layouts while preserving the current Trade basic design system and each page's task hierarchy.

Before UI implementation, define the layout direction and target-page list against [DESIGN.md](../../../DESIGN.md) and record that direction in this ticket. Do not fill unused space with decorative panels or duplicate information.
