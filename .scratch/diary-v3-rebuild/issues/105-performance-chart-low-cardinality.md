# [105] Make strategy performance readable at low cardinality

Status: needs-triage
Execution: todo
Published: 2026-10-06

Category: bug
Type: Design follow-up
User stories covered: Strategy performance review. Realized trade results and the decisions behind them.

## Observation

Found during the [whole-app page score](../../../docs/design/ui-page-score-2026-10-06.md),
where `/strategy-performance` scored **46/100**.

**The charts are wrong at low N, and low N is the normal state for this product.** A
diary user with one closed trade is the expected first-year case, not an edge case.

`apps/web/app/performance-chart.tsx:7`:

```js
const y = …, step = 640 / points.length;
```

With one point, `step` is 640 and the bar is drawn `width={step * 0.7}` = **448px wide**
against a 160px plot height. The result is a solid green slab occupying half the chart
frame — it carries no information and reads as a rendering failure. Observed on both
"Results by period" and "By symbol".

`performance-chart.tsx:9`:

```jsx
<text x={60} y={212}>{points[0]!.label}</text>
<text x={700} y={212} textAnchor="end">{points.at(-1)!.label}</text>
```

With one point `points[0]` and `points.at(-1)` are the same element, so **both axis ticks
print the same label** — `2026-09 … 2026-09`, `AAPL … AAPL`, `2026-09-29 … 2026-09-29`.

The line variant has a guard for this case (`points.length === 1 && <circle …>`), so the
cumulative P&L chart renders a single 3px dot in an otherwise empty 740×220 frame. Honest,
but it reads as a broken chart rather than as "one data point".

**Nine metrics sit above the charts** — realized gain/loss, closed trades, win rate, wins,
losses, realized drawdown, monthly Sharpe, best strategy, worst strategy. More than
double the working-memory guideline, and `DESIGN.md` names the pattern: a row of stat
tiles should be a `.ledger`, and four side by side is already "the hero-metric template,
not a design."

**Empty values carry the visual weight of data.** "Best strategy: Not recorded" and
"Worst strategy: Not recorded" render at the same large bold size as `+69.60`. Three
whole sections — By strategy, By emotion, Largest losing trades — are a heading followed
by the words "Not recorded", so most of a 2,847px page is empty states presented as
content.

**Figures are unformatted**: `Sell price 191.1`, `Average cost basis 182.4`. Owned by
[101](101-figure-formatting-consistency.md), noted here because it is on this page.

The underlying statistics are not in question. The page's own disclosure text is good and
should be preserved: it states that results use closed trades rather than deposits, how
drawdown is derived, how Sharpe is computed, and that unlabelled trades stay in totals but
not in strategy groups.

## Requested outcome

Make the page truthful and readable when there is little data, which is most of the time.
Preserve every computed statistic, the disclosure copy, the market-colour semantics, and
the PNG export.

## Implementation plan

**1. Give the chart component a cardinality floor.**
- Cap bar width so a single category cannot exceed a sane maximum regardless of `step`.
- Suppress the second axis tick when first and last labels are equal, and centre a single
  label instead.
- Decide a threshold below which a chart is not drawn at all and the table beneath it
  carries the data — one or two points is a list, not a distribution. This is the decision
  triage needs to make.

**2. Replace the nine-metric grid with a ledger.** The figures are a column of amounts;
`.ledger`/`.ledger-row` with `.ledger-row-total` closing it is the idiom the system
already defines for exactly this. At most one `.stat` survives, for a single headline
figure if one is wanted.

**3. Stop giving absent values the weight of present ones.** "Not recorded" renders at
muted body weight, not at figure size. A section whose entire content is "Not recorded"
collapses into one line or into `.empty-state`, rather than occupying a full ruled
section.

**4. Carry the chart fixes everywhere the component is used.** `PerformanceChart` is
shared; check every call site so the fix is not partial, and check the rotation PNG
export path, which the [2026-09-06 review](../../../docs/design/ui-consistency-review.md)
records as having hardcoded its own palette once before.

**Verification:** `tests/e2e/performance.spec.ts` is updated and must pass, with added
cases at **zero, one and two** closed trades — the zero and one cases are the ones that
have never been covered. Assert that a single-category bar does not exceed the capped
width, and that the axis renders one label rather than two identical ones.

## Provisional acceptance criteria

- [ ] With one closed trade, no bar exceeds the capped width and no chart reads as a solid block.
- [ ] No chart renders the same axis label at both ticks; a single category renders one centred label.
- [ ] A charted series below the agreed cardinality threshold renders its table instead of an empty or near-empty plot frame.
- [ ] The nine-metric grid is replaced by a ledger; at most one `.stat` remains.
- [ ] "Not recorded" and other absent values render at muted body weight, never at figure size.
- [ ] A section whose only content is an absent value does not occupy a full ruled section.
- [ ] Every statistic, the disclosure copy about closed trades, drawdown, Sharpe and unlabelled trades, and the market-colour semantics are unchanged.
- [ ] Zero, one and two closed-trade states are covered by tests; the zero-trade state is reachable and sensible.
- [ ] Series colours still imply no direction, and positive drawdown magnitudes still read as losses.
- [ ] Verified in all three locales, light and dark, all three market-colour preferences, at 390/768/1440.
