## Observation

The TypeScript and ESLint gates are clean (`tsc --noEmit` and `npm run lint` both exit 0),
and `eslint.config.js:8` enforces `no-unused-vars`. What no tool enforces is *formatting*:
there is no Prettier, no `eslint --fix` stylistic rules, no import-order rule. The style is
maintained by discipline, and discipline is already leaking:

`apps/api/src/app.ts` is internally inconsistent. Routes registered through helper
functions use the file's normal spacing (`app.ts:377-427`), but one route wrote itself in a
denser style with no spaces after commas or around `=>` (`app.ts:392-398`):

```ts
app.get('/api/market/rotation-monitor',async c=>{
  c.header('Cache-Control','no-store');
  const query=marketRotationMonitorQuerySchema.safeParse(c.req.query());if(!query.success)return validationError(query.error);
  ...
})
```

This is not a defect — the code works and passes every gate, which is exactly the point of
filing it. A codebase whose reviewers cannot tell a formatting slip from a deliberate local
choice spends review attention on the wrong thing. Across 968 hand-written TS/TSX files,
formatting is the one mechanical category with zero automated guardrails while the project
has automated guardrails for far subtler things (registers, figures, contrast).

## Requested outcome

One formatter, applied once across the tree, enforced in CI so formatting stops being a
review subject.

## Implementation plan

**1. Choose Prettier** (the project has no competing formatter). Add it with a config that
minimizes churn in the existing tree. Semicolon usage already varies between files, so
choose and record that policy explicitly rather than claiming one is universal. Record
the choice in `AGENTS.md`'s conventions section and the check
table.

**2. Run it once, as a single formatting-only commit**, so the change is mechanically
reviewable and does not entangle with behaviour. Generate it only through the pinned
formatter and record the command. `git diff -w` can help review whitespace, but it is not
an equivalence check: formatting may change quotes, semicolons and trailing commas, and
whitespace inside strings can affect behavior. Review the remaining diff and run the
source gates; require the formatter to be idempotent on a second run.

**3. Add `prettier --check` to the lint gate** and to the pre-merge CI from
[124](124-gate-changes-before-main.md).

**4. Re-check the app.ts route** at `392-398` as part of step 2 — it is the visible symptom
and should collapse into the same shape as its neighbours.

**Verification:** `npx prettier --check .` passes on the configured tree with explicit
ignores for generated artifacts and frozen parity inputs; a second format run changes
nothing; the formatting diff is reviewed; `tsc`, `lint`, `test:unit` still pass after it.

## Provisional acceptance criteria

- [ ] A formatter is chosen, configured, and named in `AGENTS.md`.
- [ ] The configured tree is formatted in one formatter-only commit, with generated/frozen inputs excluded, a reviewed diff and an idempotent second run.
- [ ] `prettier --check` runs in the lint gate and in CI.
- [ ] No behavioural change accompanies the formatting commit (source gates still green).
