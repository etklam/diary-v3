## Observation

Four small, unrelated defects, filed together because each is a few lines and all four sit
on the path [135](135-schedule-a-review-from-quick-capture.md) through
[139](139-workspace-help-and-capture-paths.md) already touch.

**1. The registration submit button swaps its own label.**
`routes/registration-complete.tsx` ends its form with:

```
<button type="submit" disabled={pending}>{pending ? '…' : c.create}</button>
```

`DESIGN.md` Components — Buttons is explicit: "**A control in flight keeps its label.**
`ActionButton` (`ui.tsx`) owns the state for every submitting control… It never swaps the
label, because swapping it changes the control's width mid-submit and reflows the action row
at exactly the moment the reader is watching it." This control does exactly that, and it
also skips `aria-busy`, the translated "Working…" string, and the in-flight rule that
`ActionButton` provides. `auth-form.tsx:329` on the sibling screen uses `ActionButton`
correctly, so the two halves of registration behave differently.

**2. An undocumented colour bypasses the token layer.**
`routes/market-rotation.tsx:921` hard-codes `#cbd0d7`. Reported by
`node scripts/detect.mjs --json apps/web/app`. `DESIGN.md` Tokens states that `styles.css`
and the 27 route stylesheets "consume these roles and do not hard-code a colour, radius,
duration or type size". This is a chart-adjacent literal in TSX rather than CSS, which is
how it escaped; it is still drift.

**3. `DESIGN.md` describes a four-column mobile bar that has five columns.**
Layout says: "Below 768px the sidebar becomes a sticky top app bar (safe-area aware) plus a
fixed four-column bottom bar: Diary library, Timeline, Calendar, Write diary."
`diary-navigation.tsx:88-92` renders five: Capture, Library, Timeline, Calendar, Reviews.
The code is right — the review slot is what makes the bar carry the loop end to end, which
the component's own comment explains. The document is stale.

**4. The attention severity encoding is invisible.**
`styles.css:529-536` carries the three severity bands as the width of the leading rule: 1px
`--rule` default, 2px for medium, 3px `--rule-strong` for high.
`DESIGN.md` Page recipes defends the choice against a tint — correctly, a warm slab would be
the page's only one. But a one-to-three-pixel difference in a low-chroma grey, on rows that
are never adjacent in the same band often enough to compare, communicates nothing to a
sighted reader scanning five rows. Screen readers are better served: `overview.tsx:701`
emits `attentionBandLabel` as an `sr-only` word.

This one is a **decision, not a defect** — record the ruling before changing anything. Three
options: give sighted readers the same word the screen reader gets; accept that priority is
already carried by row order (`overview-logic.ts:32-45`, which is correct and tested) and
delete the rule-width encoding as decoration that failed; or keep it and state in `DESIGN.md`
that it is a secondary cue rather than the severity channel.

## What was built

**1.** `registration-complete.tsx` uses `ActionButton pending={pending}`; the `'…'` label swap
is gone, and the screen now matches `auth-form.tsx`.

**2. The colour finding was bigger and smaller than reported.** `#cbd0d7` is not rendered
drift — it is a `getComputedStyle` *fallback* in the market-rotation export path, used only if
the stylesheet has not resolved. But recomputing all ten fallbacks against `tokens.css` showed
**nine of the ten had drifted**; the detector flagged one because only that one had drifted far
enough to stop matching the documented palette. All nine were corrected to the sRGB of the
tokens they stand in for, with a comment recording that they are a copy of the token layer and
must be recomputed when it moves. `detect.mjs` no longer reports a `design-system-color`.

**3.** The `DESIGN.md` Layout sentence now describes the shipped five-column bar and says why
Reviews is in it.

**4. Ruled: the band is no longer drawn.** The 1px/2px/3px leading-rule encoding from
[119](119-attention-list-priority.md) was removed. The original reasoning against a tint still
holds; what the evidence added is that the chosen channel carries nothing either — a two-pixel
difference in low-chroma grey, across rows rarely adjacent in the same band. It was never the
only carrier: `rowLabel` names the bucket or the reason in words, and the ordering *is* the
ranking. The `sr-only` band word stays, and is now the deliberate answer to the one real gap,
which is that linear reading cannot see order. `attention-display.ts` still computes the band
and `data-attention-band` is still emitted; nothing paints it. Recorded in `DESIGN.md` and in
the module's own doc comment.

A side effect worth naming so it is not mistaken for the motive: this also clears the
detector's `side-tab` finding. The finding was a false positive — a neutral grey rule, not a
coloured accent — and the removal is justified by the evidence above, not by the scanner.
