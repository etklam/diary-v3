# [138] The Overview single-record prompt renders a link with no name, and its copy object cannot catch that

Status: ready-for-agent
Execution: done
Published: 2026-10-29
Completed: 2026-10-29

Category: bug
Type: Defect / type safety
User stories covered: 30 (Overview).

## Observation

**The prompt designed to carry a reader from one entry to two is broken.**
`overview.tsx:812-817` renders, for an account with exactly one diary:

```
{c.singleRecordPrompt} <Link to={`/diaries/${…}`}>{c.open}</Link> ·{' '}
<Link to={`/diaries/${…}/edit`}>{c.arrangeReview}</Link>
```

`open` does not exist in any of the three locale objects (`overview.tsx:38-326`). It renders
as an empty string, so the first link has an `href`, takes focus, and is announced as a link
with **no accessible name**. This is the one mechanism in the product that advances a reader
from their first entry to the second step, and it has been shipping broken.

**Why the type system did not catch it.** `overview.tsx:32` declares
`type OverviewCopy = Record<string, string>`, so `c.open` types as `string` and compiles.
`scripts/check-locale-parity.mjs` passes too — correctly: all three locales declare the same
keys, and `open` is missing from all three. Parity is not completeness. The 114 copy objects
built with `defineCopy` (`locale-copy.ts:24`) would have failed this at compile time, because
`defineCopy` infers a closed shape from the zh-TW base and a read of an absent key is TS2339.
Overview is one of the objects that never migrated.

## Requested outcome

The single-record prompt has a name, and a missing Overview copy key becomes a compile error
rather than an empty render.

## Implementation plan

**1. Add the missing key.** `open` / `開啟` / `打开` in all three Overview locales.

**2. Migrate the Overview copy to `defineCopy`.** This is the structural half and it is
worth more than the one string: it converts every future missing key on this surface from a
silent empty render into a build failure, and it brings the file in line with the other 114.
The `tx(c, key)` escape hatch (`overview.tsx:33`) exists to index by a dynamic reason string
(`rowLabel`, `overview.tsx:600-604`) — keep it for exactly those call sites and let
everything else read properties directly so the checker can see them. Expect the migration
to surface other unused or misspelled keys; resolve each by adding the key or deleting the
read, not by widening the type back.

**3. Do not touch the empty states.** See the Comments — the critique's empty-state findings
did not survive verification and are withdrawn.

**Verification:** `npm run lint`, `npm run typecheck` (the `defineCopy` migration is the
interesting one), `npm run test:unit`, `npm run design:check`,
`node scripts/check-locale-parity.mjs`.

## Comments

Filed 2026-10-29 from the first-run UI/UX critique archived at
`.impeccable/critique/2026-10-28T16-54-37Z__apps-web-app-onboarding-and-first-run-surfaces.md`.

The empty link was found by reading the first-run path, not by any check. That is the
finding behind the finding: [130](130-locale-copy-parity.md) built the mechanism that would
have caught it and Overview was never migrated onto it, so step 2 is the part of this ticket
that matters beyond today.

**Two findings were withdrawn before implementation, in two passes.** The critique reported
`/diaries` and `/stocks` as first-run dead ends. Neither is:

- `routes/diary-list.tsx:846` renders a "Write your first diary" link on the
  unfiltered-and-empty branch, six lines below where the first read stopped.
- `routes/holdings.tsx:293` renders a filled "Record a transaction" link to `/diaries/new`.
  It reads as distant in source — roughly ninety lines below the empty sentence — but
  everything between the two is inside `data && …` guards that do not render when the
  account is empty, so on the actual empty screen the action sits directly under the
  sentence. Adding a second control there would have put two links to `/diaries/new` on one
  short page, which is worse than the state it was meant to fix.

Both errors have one cause: reading narrow windows of a branchy render and not evaluating
which branches a first-run account actually reaches. The surviving finding — the unnamed
link — was found the same way but is verifiable from the copy object alone, and the
`defineCopy` migration below is what stops the next one of its kind.

## What was built

The copy moved to `apps/web/app/overview-copy.ts` on `defineCopy`, zh-TW authoritative, with
`open` / `開啟` / `打开` added. `tx(c, key)` is gone entirely: every read is now a property
read the checker can see, including `c[row.reason]` in `rowLabel`, which typechecks because
all five `PortfolioAttentionReason` values are keys.

The guard was proved rather than assumed — renaming one read to a non-existent key produced
`TS2339: Property 'definitelyNotAKey' does not exist` before the change was reverted. That is
the behaviour `check-locale-parity.mjs` structurally cannot provide, since it compares the
three locales to each other and all three were equally missing the key.

Neither empty state was touched; see Comments.
