# [96] Rebuild the Trading principles page around reading, not managing

Status: accepted

## Observation

A design review of `/discipline` (`apps/web/app/routes/discipline.tsx`, `apps/web/app/discipline-transfer.tsx`, `apps/web/app/trade-plan.css:469-573`) scored 21/40 against Nielsen's heuristics. The deterministic slop detector returned zero findings; the problems are not decorative, they are structural. The data layer is careful — abort controllers, a navigation blocker, uncertain-state reconciliation after a failed create or import — while the surface was never designed against DESIGN.md.

Recorded findings, by severity:

**P0 — destructive action with no guard.** `remove()` (`discipline.tsx:58`) issues `DELETE` immediately. There is no confirmation, no consequence copy, and no undo. The trigger is `className="secondary"`, visually identical to Move up / Move down / Edit and sitting beside them; at 390px the four controls wrap into two rows, so a mis-tap permanently deletes a principle. DESIGN.md states every destructive action uses the danger button with consequence copy and a confirmation dialog.

**P1 — the transfer block dominates the page.** `discipline-transfer.tsx:55` puts file upload, share JSON, preview import, share title, share description, include-author and prepare-export inside a single always-expanded `<fieldset>` with inline `style={{ display: 'grid', gap: 20 }}`. Seven controls spanning two opposite directions (import in, export out) read as one flow. In `docs/design/evidence/discipline/1440.png` this block occupies roughly 45% of page height for a capability used rarely.

**P1 — row controls outweigh the content.** Four 44px secondary buttons per principle. DESIGN.md assigns row-level controls to `.quiet-button` precisely so they do not compete with content. At 390px two principles are separated by six buttons and barely 1.5 principles fit on screen. The per-row `Created: <timestamp>` line is the brightest non-content element in each row and informs no decision.

**P1 — editing happens in a detached footer form.** Choosing Edit loads the content into the page-bottom `.plan-form` (`discipline.tsx:83`) and moves focus there. The edited row keeps displaying its old text with no in-place indication, the `<legend>` reads only "Edit" without naming which principle, and every other row's controls grey out with no explanation.

**P1 — mislabeled append/replace control.** The import mode `<select>` carries `aria-label={c.heading}` (`discipline-transfer.tsx:55`), so assistive technology announces "Import and share" for the choice between appending and replacing every stored principle. The one control whose misuse destroys data is the one without a correct accessible name.

**P2 — the drawn principle uses dialog elevation.** `.discipline-draw` sets `box-shadow: var(--shadow-2)`, and `--shadow-2` aliases `--shadow-pop` (`tokens.css:174`). DESIGN.md principle 1 reserves shadow for surfaces that genuinely sit above the page — dialogs, popovers, the skip link. This is in-page content. The drawn principle also frequently repeats the first list row verbatim a few hundred pixels above it, with no indication that it is the same entry.

**P2 — page voice diverges from the workspace.** `trade-plan.css:475-491` centers h1, the lede and h2, adds `letter-spacing: 0.02em`, a one-off `1.75rem` heading size, and a container width of 720px that matches neither the reading measure (72ch / ~880px) nor the data width (1280px). Every other workspace page is left-aligned on the shared scale. `--font-serif` is documented in DESIGN.md as existing for trade-plan note surfaces only, yet this page consumes it; code and documentation disagree.

**Minor.** The `saved` flag never clears and one string ("Principles updated.") covers create, delete and reorder. The submit button and `<legend>` both read "Add principle". The 255-character cap is enforced only by `maxLength`, with no counter. The textarea carries an `aria-label` duplicating its wrapping `<label>`. Inline styles use off-scale values (`marginTop: 20`, `gap: 20`, a 20px checkbox). The draft guard and the replace-import confirmation both use `window.confirm` although the project ships a `.delete-dialog` pattern. The prepared share link is held in a `readOnly` `<textarea rows={3})` instead of an input with a copy action. Reordering costs one click and one `PATCH` per position. The empty state is a bare `<p>`, not `.empty-state`, with no example of a well-formed principle. There is no Cmd/Ctrl+Enter submit, unlike Quick Diary (`56e1f8c`).

## Requested outcome

Rebuild `/discipline` so the page serves its actual purpose — reading one of your own rules before the next decision — and so management and transfer recede to match how often they are used. Preserve every existing capability and all existing server behavior, contracts and reconciliation logic. Fold the page back into the Trade basic design system rather than keeping its private visual dialect.

## Implementation plan

Delivered as one change set, in this order.

**1. Make destruction safe (P0).**
- Replace the per-row delete trigger with `.danger-button` and route it through the shared `.delete-dialog` pattern already used elsewhere: the dialog names the consequence, quotes the first ~20 characters of the principle, autofocuses Cancel, and confirms with the danger button.
- Replace both `window.confirm` calls — the unsaved-draft guard (`discipline.tsx:17`) and the replace-import confirmation (`discipline-transfer.tsx:30`) — with the same dialog component so the page has one confirmation language.
- Give the replace/append `<select>` a correct accessible name ("Import mode") and keep a visible label.

**2. Rebalance the page (P1).**
- Header: left-aligned h1 on the shared type scale, lede below it, principle count beside the heading, and Add principle as the single filled action in the header row. Drop the centering, the `letter-spacing: 0.02em` and the one-off `1.75rem`; move the container to the shared reading measure.
- Order: header → draw → list → add → transfer disclosure.
- Transfer: wrap the whole `DisciplineTransfer` section in a collapsed disclosure labelled as advanced, and split its body into two `.panel` regions, Import and Export & share, each with its own rule. The prepared link becomes a readonly `<input>` plus a copy button. Remove the inline grid styles in favor of class-based layout on the space scale.

**3. Quiet the list rows (P1).**
- Move up / Move down become icon-only `.quiet-button` controls with `aria-label`s, retaining the existing focus-restoration behavior after a reorder.
- Edit and Delete move into a row-end control group that is always present at ≤767px and revealed on hover/focus-within at wider widths, so it never disappears for keyboard or touch users.
- The `Created` timestamp leaves the default row; it stays available in the edit state. The row becomes number, sentence, controls.
- Add Cmd/Ctrl+Enter submission to the principle textarea, matching Quick Diary.

**4. Edit in place (P1).**
- Selecting Edit turns that row into a textarea with Save and Cancel inside the row; the footer form becomes Add-only, and its `<legend>` and submit button stop repeating the same words.
- While a row is being edited, mark it as the active row and leave the remaining rows' controls enabled where it is safe to do so; where they must stay disabled, state why in one line rather than silently greying them.

**5. Reconcile with the design system (P2).**
- Remove `box-shadow` from `.discipline-draw`; express it as a sunken surface bounded by rules.
- Put a "Draw another" action inside the drawn block, and label which numbered principle was drawn so a repeat of row 01 reads as a pointer rather than duplicated content.
- Resolve the `--font-serif` contradiction by deciding whether the principles surface is a sanctioned serif surface, then updating DESIGN.md or the stylesheet to match.
- Replace the bare empty-state paragraph with `.empty-state` naming the next action and showing one example principle.

**6. Status and limits.**
- Separate create, update, delete and reorder confirmations into distinct strings in all three locales, and clear the status after it has been announced rather than leaving it on screen.
- Add a character counter to the 255-character field, shown as the limit approaches.
- Remove the redundant `aria-label` on the labelled textarea and move the remaining off-scale inline styles into `trade-plan.css` using `space-*` tokens.

**Not in scope:** drag-and-drop reordering, moving transfer to its own route, "today's principle" as a default view, and linking principles to the diaries that broke them. Each is recorded under Open triage decisions.

**Verification:** `tests/e2e/discipline.spec.ts` and `tests/e2e/discipline-share.spec.ts` are updated for the new control structure and must pass; new coverage is added for the delete confirmation and the in-place edit. Evidence captures `docs/design/evidence/discipline/1440.png`, `390.png` and `transfer-1440.png`, `transfer-390.png` are retaken.

## Triage decisions — ruled 2026-10-04 during implementation

- **Reordering** stays as quiet move buttons. Drag-and-drop is a second input model for a list that is normally 5–20 rows; the keyboard path already works and is covered.
- **No "today's principle" default view.** The drawn principle already sits above the list and now names which numbered row it is; hiding the list behind a disclosure would cost a click on every management visit for no reading gain.
- **Import and share stay on `/discipline`**, behind a collapsed disclosure. Moving them to Settings separates a capability from the only data it touches.
- **The serif voice is sanctioned.** DESIGN.md now states `--font-serif` serves the trade-plan notes *and* the trading-principle sentences, because both are authored sentences a person re-reads before deciding.
- **Confirmation, not soft delete.** An undo window needs a restore path on the server; the dialog is honest about permanence today.

## Execution record — 2026-10-04

Delivered in one change set. Deviations from the implementation plan above, all deliberate:

- **Row controls are always visible**, not hover-revealed at ≥768px. A hover-revealed control is invisible to a touch user on a hybrid device and adds a state that nothing else in this system has; quiet weight plus an icon-only reorder pair already removes the imbalance the finding named.
- **The delete trigger is an icon-only `.danger-button`** (trash, `aria-label="Delete principle"`). The plan asked for the danger button in the row and for row controls not to outweigh the sentence; a compact square keeps the red affordance without a wide red slab per row.
- **No "Add principle" button in the header.** The filled submit in the Add form is the single filled action; a second control with the same name would duplicate it and make every role query ambiguous.
- **Container width is 880px** — the documented reading/editor measure — recorded in DESIGN.md's page recipes. [93](93-desktop-workspace-space-utilization.md) should treat this as the settled width for bounded working pages unless it rules otherwise.
- **Fields use `for`/`id` association instead of wrapping labels.** The removed `aria-label` on the textarea was load-bearing for name resolution once the field had a value; explicit association fixes the duplication and the resolution together.
