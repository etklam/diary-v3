# [121] One mechanism for figure caveats, instead of repeating the sentence

Status: accepted
Execution: done 2026-10-15
Published: 2026-10-15

Category: enhancement
Type: UX copy and display layer
User stories covered: Portfolio valuation — reading figures that cover only part of the account.

## Observation

**The same caveat is written three times, in three different wordings, across two
surfaces:**

| Source | Copy |
|---|---|
| `overview.tsx:26` | "Priced positions only; unpriced cost remains separate." |
| `portfolio-valuation.tsx:11` | "Values cover priced positions only. Unpriced cost remains separate." |
| `portfolio-valuation.tsx:11` | "Concentration uses priced market value only." |

All three say the same thing, and all three are correct and necessary — `PRODUCT.md` is
explicit that portfolio valuation covers only priced holdings and that *"missing quotes
must not become zero"*. The problem is the mechanism, not the honesty: the constraint is a
property of the figures, and it is being re-stated in prose at each place a figure appears.

On `/stocks` the cost is visible. Four full-width sentences are interleaved between the
label/value pairs of the valuation grid, so the figures cannot be scanned as a group:

```
Priced market value   14,520.00     Unrealized gain / loss  +5,871.60
Unrealized return     +67.89%       Priced cost basis        8,648.40
Unpriced cost basis      842.90     Quote coverage             75.00%
Concentration uses priced market value only.        <- sentence inside the grid
Largest position   75.76% SYN       Top three positions     100.00%
Concentration is elevated (largest ≥ 25% or top three ≥ 60% of priced market value).
Oldest quote: Sep 4, 2026, 3:00 PM UTC
Quotes older than 72 hours: 3
```

The last two lines restate in prose what the table 600px above already shows per row in its
"Quote status" column — the same fact rendered three ways on one page.

This is the product's most reliable tell that copy is doing a job design should do. It is
worth fixing as a mechanism because the same pressure will apply to every future figure
that has a coverage caveat.

## Requested outcome

One caveat affordance, defined once, anchored to the figure it qualifies, with the sentence
written once. The user must not lose any of the information — the constraint is a
correctness property and dropping it is not an option.

## Implementation plan

**1. Define the affordance.** A figure that does not cover the whole account carries a
marker; the marker resolves to one note. The ledger metaphor already supplies the form — a
footnote marker on the figure and one note at the foot of the region — and it costs no
layout inside the grid. The marker must be real text with an accessible description, not a
`title` attribute, and must not rely on hover (it has to work on touch).

**2. Write the sentence once** and source all three sites from it, in all three locales.
The three current wordings differ in a way that implies a difference that does not exist.

**3. Take the sentences out of the grid.** The valuation region becomes figures only; the
notes sit below the rule that closes it.

**4. Resolve the quote-status triplication on `/stocks`.** "Oldest quote" and "Quotes older
than 72 hours" are derived from the per-row column; keep one presentation. The per-row
column is the one that supports a decision about a specific position, so the prose lines
should become the footnote, not the other way round. See [123](123-holdings-quote-status-column.md),
which owns that column's width.

**5. Check for other sites.** The three above were found by grep on one phrase; the audit
should cover every surface that renders a partially-covering figure (`/`, `/stocks`,
`/strategy-performance`, `/partners/compare`).

**Verification:** `overview.spec.ts`, `holdings.spec.ts` and the portfolio valuation unit
tests must pass. Add a case asserting the caveat text appears once per region and is
programmatically associated with the figures it qualifies.

## Execution record — 2026-10-15

`apps/web/app/figure-caveat.tsx` holds the sentence and the affordance:
`figureCaveat(locale)`, `CaveatMark`, `CaveatNote`, `CaveatNotes`. Both surfaces read it.

**It was four wordings, not three.** The audit in step 5 found a fourth — `overview.tsx`'s
`noQuote` ("Missing quotes stay separate from priced value.") — which had *no reader at
all*: an unused copy key stating the same constraint a fifth way, waiting to be picked up
by the next surface. It is deleted, along with `portfolio-valuation.tsx`'s `hint` and
`riskBasis` and `overview.tsx`'s `quoteSource`. `/strategy-performance` and
`/partners/compare` were checked and render no partially-covering figure.

**Ruling 1 — the mark goes on the label, not the figure.** The ticket's "a footnote marker
on the figure" was tried first and the test suite argued against it immediately: seven
assertions pin exact figure text (`toHaveText('123,456,850,743.83')`), and a marker inside
the value makes every one of them inexact. Weakening them was not acceptable —
[101](101-figure-formatting-consistency.md) exists because figure text drifts when nothing
pins it. The marker moved to the row's label, which is better on its own terms: a figure
column exists to line digits up, and a superscript inside it breaks that alignment, while
a label is prose and prose is where a footnote marker has always gone. Every existing
assertion stayed exact and no test needed loosening.

**Ruling 2 — `attentionPartial` stays, and is not a fifth wording.** `/`'s attention
region says "Some quotes are missing; concentration uses priced positions **while reminders
still include active holdings**". That is a different fact — the asymmetry between two
regions — not a restatement of the coverage caveat, so it keeps its own sentence.
`portfolio-attention.tsx`'s own `hint` does end with the shared constraint; that region
belongs to [119](119-attention-list-priority.md) and is folded in there rather than here.

**Ruling 3 — two notes, two marks.** `*` is coverage, `†` is quote age. Step 4 asked for
the two `/stocks` prose lines ("Oldest quote", "Quotes older than 72 hours") to become the
footnote, and they are now one `†` note carrying both facts, which also satisfies
[123](123-holdings-quote-status-column.md)'s "keep one summary line, not two" before that
ticket touches the column. `Unpriced cost basis` deliberately carries no mark: it is the
complement of the caveat, not a figure limited by it, and marking it would say the opposite
of what is true.

**Verification.** `portfolio.spec.ts` gained the case the ticket asked for: the caveat text
appears exactly once in the region, every qualified figure's `aria-describedby` contains
the note's id, the unqualified figure has none, the note carries no `title`, and
`.portfolio-valuation > dl p` is empty — the grid holds figures and labels only.
`portfolio` 4/4, `overview` 4/4, `portfolio-attention` 2/2, `portfolio-exposure` 2/2,
`integrated-baseline` 1/1. `tsc`, `eslint` and `design:check` clean.
