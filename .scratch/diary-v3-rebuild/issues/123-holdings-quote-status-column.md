# [123] Holdings gives its widest column to its least decisive fact

Status: accepted
Execution: done 2026-10-15
Published: 2026-10-15

Category: enhancement
Type: Design follow-up
User stories covered: Portfolio — reading current positions and acting on them.

## Observation

On `/stocks` at 1440 the **"Quote status" column is the widest in the table**, wraps to two
lines on every priced row, and repeats the identical string three times:

```
Stale quote · Sep 4, 2026, 3:00
PM UTC
```

It is the right-most column, so it takes the position the eye lands on last and holds it
longest. Meanwhile `Gain / loss` — the figure the page exists to show — gets a narrower
column to its left, and the header cells of the money columns wrap mid-phrase: "Average /
cost", "Current / price", "Market / value". **Maximum width for the minimum decision
value, at the cost of the figures beside it.**

The same fact is then restated twice more below the table, in prose:

```
Oldest quote: Sep 4, 2026, 3:00 PM UTC
Quotes older than 72 hours: 3
```

So quote staleness has three presentations on one page, and the per-row one — the only
version that supports a decision about a *specific* position — is the one costing the most
layout.

This is not a correctness complaint. `PRODUCT.md` is explicit that missing and stale quotes
must stay visible and must not silently become zero, and the page is honest about it. The
question is only how much of the table that honesty should consume.

## Requested outcome

A holdings table whose column widths match the decision value of their contents, with quote
staleness fully preserved and presented once.

## Implementation plan

**1. Reduce the per-row status to a mark.** A stale row needs to be identifiable at a
glance and resolvable on demand — a marker on the row's price or market value, with the
exact timestamp available to the row rather than printed in it. Keep `No quote` as a
visible state in its own right; "stale" and "absent" are different facts and the table
currently distinguishes them, which is correct.

**2. Give the reclaimed width to the money columns** so the headers stop wrapping
mid-phrase. Check the result against `DESIGN.md`'s 1280px data cap and at 768px, where the
table is tightest.

**3. Keep one summary line, not two.** "Oldest quote" and "Quotes older than 72 hours" are
derived from the same per-row data; one line below the table naming the coverage is enough.
This overlaps [121](121-figure-caveat-mechanism.md), which owns the caveat mechanism — if
that lands first, this line is a footnote and not a paragraph.

**4. Do not use colour to carry staleness.** The table already spends its colour budget on
`--market-up` / `--market-down`, and a third colour meaning would collide with the figures
it sits beside. The marker should be typographic or structural.

**Verification:** `holdings.spec.ts` must pass. Add a case asserting that a stale row is
identifiable without reading the timestamp, that the exact instant is still reachable, that
`No quote` remains distinct from `Stale quote`, and that no table header wraps mid-phrase at
1440, 1280 and 768.

## Execution record — 2026-10-15

Sequenced after [121](121-figure-caveat-mechanism.md) as the two tickets asked, so step 3
was already done when this started: the two prose lines below the table are one `†` note,
and this ticket's per-row mark is the same `†`, pointing at it. One vocabulary, not two.

**What the cell holds now.** `Stale†` for a stale quote, `No quote` for an absent one,
`Current` for a healthy one — three states, each one short word, each a word rather than a
colour. It used to be `Stale quote · Sep 4, 2026, 3:00 PM UTC` wrapped across two lines in
every priced row, which is how the least decisive fact came to own the widest column.
`white-space: nowrap` and the removal of the 160px floor let the column size to its
contents, and `th { white-space: nowrap }` spends the freed width on the money headers that
were breaking mid-phrase.

**Ruling 1 — `aria-label` on `<time>` does not work, and the test proved it.** The first
implementation put the exact instant in `aria-label` on the `<time>` element. Playwright's
`toHaveAccessibleName` returned the empty string against an element that visibly had the
attribute — correctly: `<time>` has no implicit ARIA role, and `aria-label` on a generic
element produces no accessible name. The instant now rides a `.sr-only` span inside the
`<time>`, which is real text: announced by assistive technology, carried by `textContent`
for copy, and machine-readable in `dateTime`. It cost nothing visually and it is the only
one of the two that actually works. Worth remembering before labelling any role-less
element.

**Ruling 2 — the per-row timestamp stopped being printed, and that is the trade the ticket
asked for.** Its acceptance says the instant must stay *reachable*, not visible, and
"available to the row rather than printed in it". A sighted pointer user no longer reads a
specific position's quote instant from this table; they read the state, and the footnote
gives the oldest quote and the count. The per-position detail lives on
`/stocks/:symbol`, which is where a decision about a specific position is made. Recorded
explicitly because it is a real reduction, not a free one.

**Ruling 3 — the height assertions were wrong twice and were replaced with structural
ones.** "A wrapped header is twice as tall" is not measurable here: the row height is set
by the symbol cell, and a 69px row passed nothing. What the tests assert instead is the
property itself — `white-space: nowrap` on the quote cell and on every money header (so
neither *can* wrap), plus the headline finding directly: the quote cell is no longer the
widest cell in its row.

**Verification.** `portfolio.spec.ts` carries the new cases; `portfolio` 4/4,
`portfolio-attention` 2/2, `portfolio-exposure` 2/2, `buy-ledger` 2/2,
`ledger-corrections` 1/1, `integrated-baseline` 1/1, all green, including the existing
no-horizontal-overflow assertion at both widths. `tsc`, `eslint`, `design:check` clean.
