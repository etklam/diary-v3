# [108] Rebuild Diary reminders as a page you can actually use

Status: needs-triage
Execution: todo
Published: 2026-10-06

Category: bug
Type: Design follow-up
User stories covered: Diary reminders — return to a decision when it needs attention.

## Observation

Found during the [whole-app page score](../../../docs/design/ui-page-score-2026-10-06.md),
where `/alerts` scored **52/100**. It is the lowest-scoring page in the diary loop and the
only one in that group needing more than local fixes.

Signed in with reminders seeded elsewhere but none active, the entire page is four stacked
lines of prose:

```
Diary reminders
Return to a decision when it needs your attention.
The earliest 100 active reminders, including overdue reminders.
Times shown in: Asia/Taipei
No active reminders.
Write a diary
```

**There is no way to create a reminder on the reminders page.** The only action is a
"Write a diary" text link. Reminders are created inside the diary editor's Diary reminders
disclosure, which is reasonable as a capture path but leaves this page unable to do the
thing it is named for. Compare `/stocks/alerts` (Price reminders), which scored 70 and
does carry a "Create price reminder" form — the two reminder pages have different shapes
for the same job.

**The empty state is not the system's empty state.** `DESIGN.md` defines `.empty-state`
as "a quiet sunken well that names the next action." Watchlist, Achievements, Partners,
API keys and Research Studio all use it. Here it is a bare `<p>` followed by a bare link.

**Two lines describe content that is not present.** "The earliest 100 active reminders,
including overdue reminders" explains the pagination of an empty list, and "Times shown
in: Asia/Taipei" states a display timezone with no times on screen. Both are correct
statements in the populated case and noise in the empty one.

**No section structure at all.** No rule, no heading for the list region, nothing
separating the page's explanation from its content — so with content present the
description and the first reminder would run together.

The populated state was not captured in this review (the seeded reminder was attached to
a diary and did not surface as active), so **the list rendering itself is unassessed** and
this ticket should begin by looking at it.

## Requested outcome

A reminders page that lists reminders with structure, lets you create one, and uses the
project's empty state. Preserve the diary-editor capture path, the dismiss action, the
100-reminder bound and the timezone semantics.

## Implementation plan

**1. Assess the populated state first.** Seed active, overdue and dismissed reminders and
review the list rendering before changing anything. This review only saw the empty state;
the plan below could be wrong about the list.

**2. Decide whether this page creates reminders.** Two coherent answers: add a create form
matching `/stocks/alerts`, or keep creation in the diary editor and make the empty state
point at the specific diary-editor region rather than at "Write a diary". The first makes
the two reminder pages symmetric; the second keeps a reminder tied to the decision it
belongs to, which is more in keeping with the product's thesis. **Triage must pick**, and
the choice should be recorded against whichever reading of the product principles wins.

**3. Use `.empty-state`.** A sunken well naming the next action, consistent with the five
pages that already do.

**4. Make the explanatory lines conditional.** The 100-reminder bound and the display
timezone belong to the populated state. In the empty state they say nothing.

**5. Give the list a region.** A heading and a rule, so description and content are
separated, and overdue reminders are distinguishable from merely active ones — the lede
already promises "including overdue reminders", so that distinction should be visible.

**Verification:** `tests/e2e/alerts.spec.ts` is updated and must pass, with cases for
empty, active-only, and overdue-plus-active. The empty case asserts the page offers a
reachable next action.
