# [112] Standardize empty states and list sections across the secondary pages

Status: triaged
Execution: done 2026-10-08
Published: 2026-10-06

Category: bug
Type: Cross-cutting visual bug
User stories covered: Cross-cutting Web visual consistency. Partners, API keys, ETF watchlist, diary and price reminders, watchlist.

## Observation

Found during the [whole-app page score](../../../docs/design/ui-page-score-2026-10-06.md).
Two related conventions are applied on some pages and not others, and the pages that miss
them are consistently the lowest-scoring secondary surfaces.

**1. Empty states use two different patterns.** `DESIGN.md` defines `.empty-state` as "a
quiet sunken well that names the next action; it is not a dashed outline, since nothing
there is a drop target." Applied correctly on `/stocks/watchlist`, `/achievements`,
`/partners`, `/settings/api-keys`, `/admin/research` and `/reviews/ai-reports`. Not
applied on:

| Page | Ships instead |
|---|---|
| `/alerts` | `No active reminders.` as a bare `<p>`, then a bare "Write a diary" link |
| `/stocks/alerts` | `No price reminders yet.` as a bare `<p>` |
| `/etf/watchlist` | `No ETFs followed yet.` as a bare `<p>` |

**2. A "Refresh X" button floats above an unheaded list region.** On `/partners`,
`/settings/api-keys`, `/etf/watchlist` and `/stocks/watchlist` the list region has no
heading, and a secondary Refresh button sits immediately above the empty-state well. The
result reads as a control with nothing to control, and when populated the list runs
straight on from the page description with no separation. `/stocks/watchlist` at least
has a "Watchlist (4)" heading; the other three have none.

**3. Field widths are arbitrary on the same pages.** `/partners` renders the Partner email
input at the full 1,160px content width. `/stocks/alerts` renders Symbol at 570px and the
Reminder message textarea at 1,160px. `/settings/api-keys` renders Key label at 570px.
None of these is wrong by rule — `DESIGN.md` says text inputs fill their column — but the
columns themselves were never decided, so an email field is twice the width of a symbol
field for no reason. Note that [95](95-dropdown-layout-density.md) already settled this
for `select`; text inputs were explicitly left filling their column, so this is a
column-definition question rather than a re-litigation of that ruling.

**4. Two pages state a display timezone with nothing to display.** `/alerts` and
`/stocks/alerts` both print "Times shown in: Asia/Taipei" when the list is empty.

Also recorded in the review but **deliberately not filed here**, because each needs a
ruling rather than a fix:

- **The duplicate "Quick diary" primary action** — once in the sidebar, once top-right of
  the content area, on Overview, Diary library and most workspace pages. Plausibly
  deliberate (the sidebar one is the global shortcut, the page one is contextual), but it
  does mean two identical filled buttons are visible simultaneously, against the
  one-filled-action rule. See [94](94-quick-diary-button-consistency.md), which covered
  Quick Diary button sizing and may already own this.
- **Navigation depth.** The sidebar's content measures **1,745px**. It scrolls correctly
  (`overflow-y` computes to `auto`, so nothing is unreachable), but at 1440×1080 it still
  leaves 665px below its own fold — including **Settings, Sign out and Preferences**. With
  roughly 30 destinations in the tree this is a findability cost, and the fix is an IA
  decision about what belongs in the sidebar at all, which is out of scope for a
  consistency ticket and interacts with the standing rule that navigation must serve
  capture → read → review before anything else.

## Requested outcome

Apply the two existing conventions — `.empty-state` for empty datasets, a headed region
for every list — to the pages that miss them, and decide the field columns on those same
pages. Keep resource failures visually distinct from empty data, which the system already
requires and which the Refresh buttons currently blur.

## Implementation plan

**1. Convert the three bare-paragraph empty states** on `/alerts`, `/stocks/alerts` and
`/etf/watchlist` to `.empty-state` wells naming a next action.

**2. Give each list region a heading and a rule**, so the page description and the content
are separated. `/partners`, `/settings/api-keys` and `/etf/watchlist` need one;
`/stocks/watchlist` has one already.

**3. Decide where Refresh belongs.** Candidates: beside the list heading as a quiet
control, or removed in favour of the scoped retry the failure state already provides. The
review's reading is that an unconditional Refresh button is the weaker option — `DESIGN.md`
asks for "resource failures … with scoped retry controls", which implies retry is a
failure affordance rather than a permanent one. The same argument applies to the
unconditional "Try again" button on `/stocks`, which sits beside "Record a transaction"
with no error present. **Triage decides whether Refresh survives.**

**4. Define the field columns** on `/partners`, `/stocks/alerts` and `/settings/api-keys`
so a single-line field is not full-bleed at 1,160px.

**5. Make the timezone line conditional** on there being times to display.

**Verification:** the affected pages' existing e2e specs are updated and must pass. Add
one assertion per converted page that the empty state is reachable and names an action.

## Settled during triage

**Scope reduced by 108, 2026-10-08.** `/alerts` is done: it now renders `.empty-state` with
a next action, states the 100-reminder bound and the display timezone only when reminders
are shown, and gives its list a headed region with a rule. Two of this ticket's three bare
empty states remain (`/stocks/alerts`, `/etf/watchlist`), and the conditional-timezone item
now applies to `/stocks/alerts` only. 108 also moved row controls to quiet weight on
`/alerts`, which is the convention step 3 should stay consistent with.

**1. Step 3: Refresh survives, and moves onto the list heading's baseline.** The review's
reading was that an unconditional Refresh is the weaker option. It does not survive
contact with what these lists are: **every one of them can change without the reader** — a
partner accepts an invitation or sends one (`partners.spec.ts` and
`stock-note-sharing.spec.ts` both use `Refresh partners` to observe exactly that across two
browser contexts), an agent's use updates a key's last-used time, and quotes and ETF
closes move on their own. Removing the control would delete a capability to satisfy a
reading of a rule about *retry*, which is a different thing.

So the rule is: **a retry belongs to a failure and appears only with one; a refresh belongs
to a list whose data can change without you, and sits on its heading's baseline at
secondary weight.** That is what [106](106-watchlist-row-controls.md) already shipped for
`/stocks/watchlist`, and it is what the complaint was actually about — a control floating
above an unnamed region reads as a control with nothing to control. `/partners`,
`/settings/api-keys` and `/etf/watchlist` now have the heading the control sits on.

**2. `/stocks`'s unconditional "Try again" was a mislabel, not a stray control.** It
re-reads the ledger and the quotes, which is a refresh; it was only ever wrong because it
said "Try again" with no failure in sight. It is now `Refresh prices`. The scoped retries
inside each failed section are unchanged, and `portfolio-exposure.spec.ts` — which used
this control to trigger a reload — was updated with it.

**3. Step 4: two field columns, not per-page widths.** `.field-sm` (18rem) for a symbol or
a threshold and `.field-md` (28rem) for an email or a label, applied to the field's grid
cell so the input still fills its column as `DESIGN.md` requires. A textarea keeps the
full column: it holds prose, and prose wants the measure. This is the column definition
[95](95-dropdown-layout-density.md) left open, not a re-litigation of it.

**4. `/etf/watchlist`'s read failure gained a scoped retry.** Moving the refresh onto the
list heading put it inside the loaded branch, and the failure branch had been relying on
that one floating button for recovery. A failure now carries its own retry, which is what
the empty-versus-failure pattern asks for anyway.

**5. The two deferred findings are filed, not ruled.** [115](115-duplicate-quick-diary-action.md)
for the duplicate Quick diary primary action and [116](116-sidebar-navigation-depth.md)
for navigation depth. Both touch the capture-first principle, and both have two defensible
readings; taking either ruling inside a consistency ticket would have been the wrong place
to decide it.
