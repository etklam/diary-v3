# [139] Help leaves the product at sign-in, and the full editor is behind an unlabeled chevron

## Observation

**Two findings, one cause: a path that exists and is not visible.**

**Help is public-only.** `/guide` is a real page with five task-oriented entries
(`routes/guide.tsx:20-51`). `PublicNavLinks` (`nav.tsx:647`) renders it in the public header,
the public drawer and the public footer. The workspace shell renders none of them —
`NavigationLinks` (`nav.tsx:214`), `AccountLinks` (`nav.tsx:395`) and `MobileMenu`
(`nav.tsx:428`) have no guide entry. Signing in removes the help.

It is not strictly unreachable: `destinations.ts:187` lists `/guide`, so the command palette
finds it by name. That is recall, not recognition — it requires knowing the page exists and
what it is called. For a product whose interface is dense with domain terms a new investor
has to learn (論點 / 複盤 / 持倉集中度 / 大師持倉, thesis / review / concentration), losing the
one explanatory surface at the moment the reader enters the thing being explained is the
wrong way round.

**The full editor is behind an icon.** `quick-entry.tsx:62`:

```
<DisclosureSummary aria-label={c.more}></DisclosureSummary>
```

An empty summary — the chevron from `icons.tsx` and nothing else. Its entire contents is one
link, "Write a full diary" → `/diaries/new`. That is the only sidebar route to the surface
holding thesis, risk, execution, transactions, reminders and review scheduling.

Assistive technology is served: the `aria-label` names it. A sighted reader sees a triangle.
A disclosure holding exactly one item also saves nothing — it trades a visible second action
for a click plus a guess.

Note what this ticket does **not** claim. The quick path being the default is correct and
deliberate, and `diary-navigation.tsx:84-86` states why. The defect is that the *other* path
is unnamed, not that it is secondary.

## Requested outcome

A signed-in reader can find help from the workspace, and both capture paths are legible
without opening anything.

## Implementation plan

**1. Put the guide in the pinned account block.** `AccountLinks` (`nav.tsx:395`) renders
into `.desktop-preferences`, pinned to the foot of the sidebar and always visible —
[116](issues/116-sidebar-account-pinning.md) put it there precisely so these links never fall
below the fold. Add the guide above Achievements, with the `compass` icon
`destinations.ts:187` already assigns it. Add it to `MobileMenu` through the same
`NavigationLinks` path so the drawer matches.

**2. Give the guide a signed-in register.** Its current intro — "Private routes ask you to
sign in first and return you to the task" (`routes/guide.tsx:18`) — is written for a guest
and is noise once signed in. Swap the closing section too: a signed-in reader does not need
"Create an account". Use `useSessionState()`, which the page can already reach. Leave the
five tasks as they are; they are the right content.

**3. Name the second capture path instead of hiding it.** Replace the empty chevron
disclosure with a plain second link rendered beside the quick action — the same
`quick-capture-options` link, promoted out of the disclosure. One filled action (Quick diary)
and one quiet link (Write a full diary) is the arrangement `DESIGN.md` already prescribes for
an action row, and it removes a disclosure whose only content was one item.

Keep the mobile branch as it is: `CaptureChoices` already renders only the quick link when
`mobile` is true (`quick-entry.tsx:45`), and the drawer's capture section is a different
layout question.

**4. Do not build a tour.** No overlay, no coach marks, no dismissible checklist. The
product's own principle is that the tool disappears into the task; the fix here is making
two existing surfaces visible, not adding a layer over them.

**Verification:** `npm run lint`, `npm run typecheck`, `npm run test:unit`,
`npm run design:check`. E2E navigation specs assert sidebar contents and may need updating.

## What was built

**The guide had to move shells before a link to it was worth adding.** `/guide` was
`isPublicContentPath`, so it rendered in the public shell even for a signed-in reader —
following a sidebar link to it would have replaced the workspace with the public header,
losing the sidebar the guide is explaining. It is now `isGuestPublicPath`: public chrome for a
guest, workspace chrome once signed in. `tests/unit/shell-chrome.test.ts` passes unchanged
(32 cases).

The link sits in `AccountLinks` — the block pinned to the foot of the sidebar by
[116](116-sidebar-account-pinning.md), so it cannot fall below the fold — and in the mobile
drawer's Account group. `navigationOwner` learned `/guide` so it takes the selection
treatment. The page's intro and closing now differ for a signed-in reader; the five tasks do
not.

**The empty chevron is retired.** `CaptureChoices` renders the full editor as a named quiet
link under the filled Quick diary action. The disclosure, its popover, its outside-pointerdown
listener, its Escape handling and its blur handling are all deleted — a disclosure holding one
item was buying nothing. `.quick-entry-controls` became a single stacked column.
